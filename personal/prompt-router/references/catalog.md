# 提示词目录

| 模板（链接到正文） | 适用意图与交付物 | 排除条件 |
| --- | --- | --- |
| [01 苏格拉底提问](01-socratic-questioning.md) | 用户有困惑、卡住或怀疑问错了问题，希望通过逐轮追问厘清真正想解决的事。交付包含事实、假设与关键变量的六项小结，以及待用户确认的可行动新问题。 | 用户的问题与目标已明确，且当前要求直接给判断、建议、决策或行动方案。 |
| [02 双层解释法](02-two-layer-explanation.md) | 用户想学懂一个明确的概念或问题，既需要生活化例子，也想理解专业术语、核心机制和适用边界。交付小白版和专业版、术语对照、易错点及三道自测题。 | 用户明确只要一句定义、只要指定深度的一层解释，或需要先通过逐轮提问厘清自己想问什么。 |
| [03 反向拆解](03-reverse-analysis.md) | 用户给出或指出某个具体成品，想弄清它为何有效，以及哪些做法能迁移到自己的场景。交付结构与关键选择分析、3 到 5 条可复用规律、操作清单和一个小练习。 | 用户只是用案例辅助理解抽象概念，或只要求总结成品内容、直接修改成品。 |
| [04 纵横分析法](04-longitudinal-comparative-analysis.md) | 用户需要对明确对象做可追溯的深度研究，结合历史演化、同类对比和未来路径判断。交付带来源及日期的时间线、对比表、详细分析和三条未来路径，默认篇幅 1 万至 3 万字。 | 用户只要简短背景、单项事实、快速对比，或希望拆解单个成品并提炼可迁移做法。 |
| [05 事实核查](05-fact-checking.md) | 用户质疑一条具体说法的真实性或其证据能否支持结论。把可核查事实、推论和价值判断拆开，交付事实证据分级、推理漏洞、补强后的说法和当前可信程度。 | 用户只想查一个事实或定义，或主要想综合研究某个对象的历史、同类差异和未来走势。 |
| [06 专家会诊](06-expert-panel.md) | 用户面对涉及多种专业取舍的具体问题，需要三种互补视角提出路径、互相质疑，再形成综合建议。交付推荐方案、适用条件、最大风险、退出条件和第一步行动。 | 用户主要想厘清自己究竟要问什么、核查某条具体说法，或只要求单一专业视角。 |
| [07 第一性原理](07-first-principles.md) | 用户已有待解决的问题，想检视惯例或原方案的假设，从基本事实、目标、资源和约束推导可行路径。交付原方案的表面修补点、新路径、成立前提和第一步验证。 | 用户主要想通过追问确定自己要解决的问题、从一个优秀案例提炼规律，或综合多个专业视角来做取舍。 |
| [08 跨领域借解](08-cross-domain-analogies.md) | 用户有具体卡点，希望从至少三个彼此差异较大的领域寻找结构相近的历史案例，借鉴其中解决机制。交付三种适配当前处境的机制及一个低成本实验。 | 用户主要想从本问题的基本事实重新推导方案、拆解自己已指定的单个范例，或只想用类比理解概念。 |
| [09 双向钢人论证](09-double-steelman.md) | 用户在两个可辨认的选项之间犹豫，想充分论证双方、找出决定取舍的变量。先交付双方最强论据和一个关键问题，收到回答后给出判断、理由、适用条件和下一步行动。 | 用户主要想通过逐轮追问确定问题本身，或希望从多个专业视角生成并综合方案。 |
| [10 用最小实验替代空想](10-minimum-experiment.md) | 用户已有待验证的想法或选择，希望用实际反馈检验最可能改变决策的假设。交付低成本、可逆的实验方案，包括周期、投入、观测指标、继续与停止条件，以及明天可做的第一步。 | 用户主要想充分论证两个选项，或想先从其他领域寻找可借鉴的机制。 |
| [11 挖掘隐藏天赋](11-hidden-talents.md) | 用户想通过多轮生涯访谈，从具体经历发现被忽视的优势、能量模式与适合的工作环境。每轮一问，覆盖四条主线，最后交付约一万字的《个人天赋使用说明书》和 30 天验证实验。 | 用户只想厘清当前的单一困惑、验证一个已有想法，或只需要直接给出职业选项。 |
| [12 人生设计术](12-life-design.md) | 用户想通过多轮访谈探索未来几种人生方向，并尝试用原型验证。交付 8000 到 12000 字的《个人人生设计蓝图》，包括三个不同的五年版本和可开始的原型行动。 | 用户主要想从过往经历识别自己的优势，或只想比较两个已有选项、试验一个已有想法。 |

## 维护约定

- 在本目录下为每个模板新建一个 Markdown 文件，使用稳定的文件名和易辨认的标题。保留用户给出的 Prompt 正文，除非用户要求修改。
- 在上表添加一行，用相对链接指向该文件。用用户可能提出的任务描述来写适用意图，同时注明预期交付物。排除条件只记录会误选的相近场景。添加首条记录时移除上方的空库说明。
- 如有变量，在正文外注明每个变量的含义、是否必需和可从哪里取值。保留正文中已有的占位符写法。
- 有相近条目时，对照一条应该匹配和一条容易误匹配的用户请求，检查目录能否区分两种情况。
